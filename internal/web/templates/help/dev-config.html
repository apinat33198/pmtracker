config อยู่ในไฟล์ JSON (บนเซิร์ฟเวอร์คือ /etc/pmtracker/config.json ซึ่ง install.sh คัดลอกจาก ~/pmtracker/config.json ให้แก้ไฟล์ในโฟลเดอร์ repo ไม่ใช่ใน /etc) key ที่สะกดผิดทำให้โปรแกรมไม่เริ่ม พร้อมบอกว่าผิดตรงไหน ค่าใน config ใช้ตอนเริ่มโปรแกรม แก้แล้วต้องรีสตาร์ต site, task, vendor, ปฏิทิน และผู้ใช้จัดการในหน้าเว็บ ไม่ใช่ใน config

เซิร์ฟเวอร์และข้อมูล

keyค่าเริ่มต้นความหมาย
timezoneAsia/Bangkoktimezone ของทุกวันที่ในแอป
listen:8080ที่อยู่ที่รอ request ถ้า cloudflared อยู่เครื่องเดียวกันใช้ 127.0.0.1:8080 ถ้าอยู่คนละเครื่องใช้ 0.0.0.0:8080 แล้วจำกัดด้วย firewall
public_url(ว่าง)ที่อยู่ที่ผู้ใช้เปิด เช่น https://pm.apin.at ถ้าเป็น https จะเปิด Secure cookie, HSTS และไม่รับรหัสผ่านผ่าน HTTP จากเครื่องอื่น ใช้ในลิงก์ของ digest และลิงก์ setup
data_filepmtracker-data.jsonไฟล์ข้อมูล บนเซิร์ฟเวอร์ใช้ /var/lib/pmtracker/data.json
trusted_proxies127.0.0.1, ::1proxy ที่เชื่อ X-Forwarded-For ได้ ใส่ IP ตรงตัวของเครื่อง cloudflared ถ้าไม่ได้อยู่เครื่องเดียวกัน ไม่อย่างนั้นการล็อกรหัสผิดจะนับทุกคนเป็นคนเดียว

ปฏิทินและรอบ PM

keyค่าเริ่มต้นความหมาย
google.credentials_file(ว่าง)ไฟล์ key ของ service account ถ้าไม่มีไฟล์ โปรแกรมยังทำงานแต่ไม่ได้ต่อ Google
sync_interval_minutes15รอบการอ่านปฏิทิน
sync_lookback_months24อ่านย้อนหลังกี่เดือนตอน sync เต็ม ใช้ 36 ถ้า audit ต้องการประวัติ 3 ปี
calendars[]ปฏิทินตั้งต้นตอนสร้างไฟล์ข้อมูลครั้งแรกเท่านั้น (id, label, pm_only) หลังจากนั้นจัดการในหน้าเว็บ
keywords[]คำเพิ่มเติมที่บอกว่านัดเป็น PM เช่น "MA visit"
holidays[]วันหยุดแบบ "2026-12-31" ใช้แนะนำวันนัด เพิ่มวันหยุดราชการทุกปี
defaults.interval_months3รอบ PM ของ task ใหม่
defaults.window_days21ช่วงจอง ± วัน
defaults.lead_days30เตือน Due soon ล่วงหน้ากี่วัน
defaults.grace_days7ช่วงผ่อนผันก่อน Overdue

Digest, ฟีด, backup และ activity

keyค่าเริ่มต้นความหมาย
digest.time(ว่าง = ปิด)เวลาส่ง digest แบบ "08:00"
digest.telegram_bot_token, digest.telegram_chat_id(ว่าง)bot และ chat ที่ส่ง ถ้าว่าง digest เขียนลง log เท่านั้น ไฟล์ config ต้องอ่านได้เฉพาะ service
feed.token(ว่าง = ปิด)token ของฟีด /forecast.ics?token=… อย่างน้อย 24 ตัวอักษร สร้างด้วย openssl rand -hex 24 ใส่ค่าตัวอย่างโปรแกรมไม่เริ่ม
backup.time02:30เวลาสำรองรายวัน หรือ "off"
backup.keep_days30เก็บไฟล์สำรองกี่วัน
backup.dirbackups ข้างไฟล์ข้อมูลโฟลเดอร์สำรอง ถ้าอยู่นอก /var/lib/pmtracker ต้องเพิ่ม ReadWritePaths ใน systemd unit
activity.keep_days90เก็บ activity log กี่วัน (ตามนโยบาย ISO 27001 ของบริษัท)

Sign in

keyค่าเริ่มต้นความหมาย
auth.anonymous_accessnone"none" ทุกหน้าต้อง sign in หรือ "viewer" คนที่ยังไม่ sign in ดูได้อย่างเดียว ใช้ "none" กับเซิร์ฟเวอร์ที่เข้าถึงจากอินเทอร์เน็ต
auth.session_hours12sign in อยู่ได้กี่ชั่วโมงถ้าไม่ติ๊ก Keep me signed in
auth.users[]บัญชีสำรอง {"username", "password", "role"} ใส่ hash จาก pmtracker hash-password

คำสั่งและ flag

pmtracker [-config file | -demo] [serve|check|sync|digest]
pmtracker hash-password
คำสั่ง / flagทำอะไร
serve (ค่าเริ่มต้น)เปิดเว็บ พร้อม sync, backup และ digest ตามเวลา
checkตรวจ key และทุกปฏิทิน นับ event และผลการจับคู่ ไม่เขียนข้อมูล
syncsync ทุกปฏิทินหนึ่งรอบแล้วจบ
digestพิมพ์ข้อความ digest ของวันนี้
hash-passwordอ่านรหัสผ่าน (ไม่แสดงบนจอ) แล้วพิมพ์ hash
-configไฟล์ config
-demoใช้ข้อมูล demo ไม่ต้องมี Google (เริ่มใหม่ทุกครั้ง ยกเว้นใช้ -keep)
-keepdemo: เก็บข้อมูลที่แก้ไว้ข้ามการรีสตาร์ต
-addr, -dataแทนค่า listen และ data_file
-today 2027-01-15สมมติว่าวันนี้เป็นวันอื่น สำหรับ demo และทดสอบ
