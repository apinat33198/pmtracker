ข้อมูลทั้งหมด (site, task, vendor, visit, การตัดสินใน inbox, job, finding, incident, ผู้ใช้) อยู่ในไฟล์เดียว ระบบสำรองไฟล์นี้ทุกวัน จัดการได้ที่ Admin › Backups

สำรองรายวัน

  • {{if eq .Cfg.Backup.Time "off"}}เซิร์ฟเวอร์นี้ปิดการสำรองรายวันอยู่ (backup.time เป็น "off"){{else}}ทุกวันเวลา {{.Cfg.Backup.Time}} น.{{end}} บีบอัดเป็น .json.gz อ่านได้เฉพาะ service
  • เก็บ {{.Cfg.Backup.KeepDays}} วัน (backup.keep_days) แล้วลบอันเก่า
  • ถ้าเซิร์ฟเวอร์ปิดอยู่ตอนถึงเวลา จะสำรองให้ตอนเปิดเครื่อง
  • กด Back up now เพื่อสำรองทันที เช่น ก่อนอัปเดตหรือก่อน import ครั้งใหญ่
  • Download ดาวน์โหลดไฟล์สำรอง (ถูกบันทึกใน activity log)

ค่าเริ่มต้นเก็บไฟล์สำรองไว้บนเซิร์ฟเวอร์เดียวกับข้อมูล ถ้าดิสก์เสียจะเสียทั้งคู่ ให้ตั้ง backup.dir ไปที่ share บน NAS (วิธีตั้ง) ทำ backup ของ container ด้วย Proxmox Backup Server และดาวน์โหลดเก็บไว้ที่อื่นเป็นระยะ

ในไฟล์สำรองมีอะไร

  • ข้อมูลทั้งหมดรวมhash ของรหัสผ่าน จึงต้องเก็บเป็นความลับ
  • ไม่มีกุญแจที่ใช้เซ็น cookie การ sign in ไฟล์ที่หลุดไปจึงใช้ปลอม session ไม่ได้
  • ไม่มี activity log ซึ่งเก็บแยกต่างหาก

Restore

  1. เลือกไฟล์สำรองในรายการแล้วกด Restore… หรือใช้ Restore from a file เพื่ออัปโหลดไฟล์ .json.gz ที่ดาวน์โหลดไว้ หรือไฟล์ข้อมูล .json (ใช้ย้ายเซิร์ฟเวอร์)
  2. พิมพ์ restore เพื่อยืนยัน แล้วกดปุ่ม restore

สิ่งที่เกิดขึ้น:

  • ระบบตรวจไฟล์ก่อน ถ้าไม่ใช่ไฟล์สำรองของ PM Tracker หรือข้อมูลไม่ถูกต้อง จะไม่เปลี่ยนอะไร ไฟล์จาก PM Tracker เวอร์ชันใหม่กว่าจะถูกปฏิเสธพร้อมข้อความว่าให้อัปเดตก่อน
  • บันทึกข้อมูลปัจจุบันเป็นไฟล์สำรอง “before restore” ก่อน
  • แทนที่ข้อมูลทั้งหมด สิ่งที่บันทึกหลังเวลาของไฟล์สำรองจะหาย รวมถึง finding และ incident
  • ทุกคนถูก sign out

ใช้ restore เมื่อเกิดเหตุร้ายแรงหรือย้ายเซิร์ฟเวอร์เท่านั้น ถ้าแก้ข้อมูลผิดไม่กี่รายการ ให้แก้กลับในหน้าเว็บ และ restore เฉพาะไฟล์ที่คุณสำรองเองเท่านั้น เพราะไฟล์สำรองมีบัญชีและรหัสผ่าน
