ฟังก์ชันและ method หลักของแต่ละ package เรียงตามที่เจอเมื่ออ่านโค้ด ชื่อเขียนแบบ package.Type.Method รายชื่อในหน้านี้ถูกตรวจโดยเทสต์ TestHelpFunctionsExist ถ้าเปลี่ยนชื่อหรือลบฟังก์ชันแล้วไม่แก้หน้านี้ เทสต์จะไม่ผ่าน รายการเต็มดูได้ด้วย go doc -all ./internal/<package>

cmd/pmtracker

ฟังก์ชันหน้าที่
main.mainอ่าน flag (-config, -demo, -keep, -addr, -data, -today) และคำสั่ง แล้วเรียก run
main.runโหลด config หรือ demo, เลือกแหล่งปฏิทิน (Google, ไม่ได้ต่อ, หรือ demo), เปิด store, สร้าง catalog ตั้งต้น, รันคำสั่ง หรือเริ่ม server พร้อม syncer, backup และ digest
main.demoSeedsync ปฏิทิน demo สองรอบ ยืนยัน visit เก่า และใส่ job, finding, incident ตัวอย่าง
main.checkคำสั่ง check: ทดสอบ key และทุกปฏิทิน นับ event และผลการจับคู่ โดยไม่แตะ store
main.hashPasswordคำสั่ง hash-password: อ่านรหัสผ่านแบบไม่แสดงบนจอ แล้วพิมพ์ hash สำหรับ auth.users

internal/config

ฟังก์ชันหน้าที่
config.Load, config.Parseอ่านไฟล์หรือ bytes, ใส่ค่าเริ่มต้น, ตรวจทุกค่า และรวมปัญหาทั้งหมดไว้ใน error เดียว
config.Config.Locationtimezone ของงาน (ทุกวันที่ในแอปคิดตาม timezone นี้)
config.Config.IsHolidayวันนั้นอยู่ใน holidays หรือไม่ ใช้แนะนำวันนัดแทนวันหยุด
config.Config.HTTPSpublic_url เป็น https หรือไม่ ใช้ตัดสิน Secure cookie, HSTS และการไม่รับรหัสผ่านผ่าน HTTP
config.Config.TrustedProxyที่อยู่นั้นเป็น proxy ที่เชื่อ X-Forwarded-For ได้หรือไม่
config.Config.SecretProblemsปัญหาของความลับใน config เช่น feed token สั้นเกินไปหรือเป็นค่าตัวอย่าง server ไม่เริ่มถ้ามี
config.RoleRankลำดับของบทบาท viewer < editor < admin

internal/core

Snapshot และ forecast

ฟังก์ชันหน้าที่
core.Buildหัวใจของแอป: จาก Inputs สร้าง Snapshot ที่มี event พร้อมผลจับคู่, visit, forecast ทุก task, สรุปต่อ site และ vendor, upcoming, inbox, job, finding และ incident
core.NewMatcher, core.Matcher.Matchตัดสินว่า event เป็น PM ไหม ของ site, system และ vendor ไหน ผูกกับ task ใด พร้อมเหตุผล (Reasons) และสิ่งที่ขาด (Missing) ตามลำดับใน การจับคู่
core.NewForecaster, core.Forecaster.Forคำนวณ forecast ของ task หนึ่งจาก visit: PM ล่าสุด, นัด, วันครบกำหนด (rolling หรือ fixed slots), สถานะ, วันแนะนำแทนวันหยุด และสามรอบข้างหน้า
core.SortForecastsเรียงตามความเร่งของสถานะ แล้วตามวันที่เหลือ
core.Digestข้อความ digest รายวันจาก snapshot (ว่างถ้าไม่มีอะไรต้องทำ)
core.ForecastICSฟีด iCalendar ของวันครบกำหนดและสามรอบข้างหน้า
core.AddMonthsClampบวกเดือนแบบไม่ล้นเดือน (30 พ.ย. + 3 เดือน = 28 ก.พ.)
core.Day, core.DaysBetweenตัดเวลาเหลือวัน และนับวันระหว่างสองวันโดยไม่สนเวลาออมแสง
core.NearestWorkingDayวันทำงานที่ใกล้ที่สุดเมื่อวันครบกำหนดตรงวันหยุด

Catalog และ import

ฟังก์ชันหน้าที่
core.Catalog.Validateตรวจความสอดคล้องทั้งหมด: รหัสไม่ซ้ำ, task ชี้ site, system, vendor ที่มีจริง, fixed slots มีวันแรก ฯลฯ ใช้ทุกครั้งที่บันทึกและตอน restore
core.Catalog.Tidyจัดเรียงและล้างข้อความก่อนบันทึก
core.Catalog.AddTaskเพิ่ม task พร้อมสร้าง ID ที่ไม่ซ้ำ
core.Catalog.EnsureVendor, core.Catalog.EnsureSystemหา vendor หรือ system จากชื่อหรือชื่ออื่น ถ้าไม่มีก็สร้าง (ใช้ในฟอร์มและ import กันการซ้ำ)
core.Catalog.TasksAt, core.Catalog.TaskLabeltask ของ site หนึ่ง และชื่อที่อ่านง่ายของ task
core.ApplyImportอ่าน CSV import ใส่ลง catalog สำเนา คืนผลรายบรรทัดและ visit ที่จะบันทึก ไม่มีผลถ้ามี error
core.ParseDateอ่านวันที่สามรูปแบบรวมปี พ.ศ.

Job, finding และ incident

ฟังก์ชันหน้าที่
core.Job.Cleanจัดข้อความและตรวจ job
core.Finding.Clean, core.Finding.CheckLinksตรวจ finding: ค่าที่เลือก วันที่ การปิดต้องมีสิ่งที่ทำ; และลิงก์ไป site, task, finding เดิม (repeat ต้องเก่ากว่าและอยู่ site เดียวกัน)
core.StatsOf, core.FindingsBySite, core.FindingsByVendorตัววัดของ finding และแยกตาม site และ vendor
core.Incident.Cleanตรวจ incident: incident ต้องมีผลกระทบ near miss ต้องไม่มี, ผลที่แย่ที่สุดไม่น้อยกว่าผลจริง, เวลาเรียงถูก, เงื่อนไขการปิด
core.Incident.CheckLinksลิงก์ไป site, task, finding และ incident เดิม
core.RiskOflikelihood × consequence เป็นคะแนนและระดับ (low, medium, high, extreme)
core.IncidentChangesอธิบายความต่างระหว่างสองเวอร์ชันของ incident เป็นข้อความสำหรับ timeline
core.NextIncidentRefเลขอ้างอิงถัดไป INC-ปี-ลำดับ
core.IncidentStatsOf, core.RiskMatrixตัววัดของ incident และตาราง 5 × 5 ตามความเสี่ยงปัจจุบัน
core.buildFindings, core.buildIncidentsสร้าง view (วันที่, อายุ, การเกิดซ้ำ, ระดับความเสี่ยง) และเรียงลำดับสำหรับ snapshot

internal/store

ฟังก์ชันหน้าที่
store.Openอ่านไฟล์ข้อมูล (หรือเริ่มว่าง), normalize, อัปเกรดเวอร์ชัน, เปิด activity log และย้ายบันทึกเก่าออกจากไฟล์ข้อมูล
store.Store.Inputs, store.Store.Catalogสำเนาข้อมูลสำหรับ core.Build และสำเนา catalog (แก้สำเนาได้โดยไม่กระทบ store)
store.Store.UpdateCatalogแก้ catalog แบบ transaction: ใช้ฟังก์ชันกับสำเนา, Tidy, Validate, ล้างสิ่งที่อ้างถึง task หรือปฏิทินที่หายไป แล้วบันทึก
store.Store.ApplySync, store.Store.SetSyncErrorรวมผล sync เข้า mirror และบันทึกข้อผิดพลาดของการ sync
store.Store.Decide, store.Store.Undecide, store.Store.AddRule, store.Store.DeleteRuleการตัดสินใน Review inbox และกฎที่จำไว้
store.Store.Mark, store.Store.Unmark, store.Store.AddManual, store.Store.DeleteManualยืนยันหรือ mark missed visit และ visit ที่บันทึกเอง
store.Store.AddJob, store.Store.UpdateJob, store.Store.DeleteJobad-hoc job
store.Store.AddFinding, store.Store.UpdateFinding, store.Store.DeleteFindingfinding; ลบแล้ว repeat ที่ชี้มาเสียลิงก์ และ incident ที่ผูกไว้เสียลิงก์
store.Store.AddIncident, store.Store.UpdateIncident, store.Store.DeleteIncidentincident; Add ให้เลขอ้างอิง, Update บันทึกสิ่งที่เปลี่ยนและข้อความลง timeline และไม่ยอมให้แก้ timeline, เลขที่ หรือ site
store.Store.Users, store.Store.SaveUser, store.Store.DeleteUser, store.Store.SessionSecretบัญชีผู้ใช้ และกุญแจเซ็น cookie (สร้างครั้งแรกที่ใช้)
store.Store.Log, store.Store.LogFrom, store.Store.Auditเขียน activity ที่ไม่เปลี่ยนข้อมูล (sign in, ดาวน์โหลด) และอ่านรายการล่าสุด
store.Store.Export, store.Store.Restoreข้อมูลทั้งหมดเป็น JSON (ไม่รวมกุญแจ session) และแทนที่ด้วยไฟล์สำรองหลังตรวจทุกส่วน, sign out ทุกคน
store.Store.save, store.Store.writeเขียนไฟล์แบบ atomic (temp file, fsync, rename, fsync โฟลเดอร์) แล้วเขียน activity ของการเปลี่ยนนั้น
store.state.normalize, store.state.tidyFindings, store.state.tidyIncidents, store.Store.cleanupซ่อมสิ่งที่อ้างถึงข้อมูลที่ไม่มีแล้ว และทำให้เลขถัดไปมากกว่าเลขที่ใช้อยู่ทั้งหมด
store.ActivityLog.Append, store.ActivityLog.Recent, store.ActivityLog.Eachactivity log: เขียนต่อท้ายไฟล์ของวัน, อ่านล่าสุด, อ่านทั้งหมดสำหรับ CSV และลบไฟล์ที่เก่ากว่าระยะเก็บ

web.Server.incidentsPage, web.Server.addIncident, web.Server.editIncident, web.Server.noteIncidentหน้า Incidents, บันทึก, แก้ (รวมกฎว่า admin เท่านั้นที่ยอมรับความเสี่ยงสูงได้) และเพิ่มข้อความใน timeline
web.Server.restorerestore จากไฟล์ในรายการหรือไฟล์ที่อัปโหลด หลังบันทึกข้อมูลปัจจุบันเป็นไฟล์สำรองก่อน
web.csvCellกันข้อความที่ Excel จะตีความเป็นสูตร
web.Server.helpPageHandler, web.Server.helpSearchคู่มือนี้: render หน้า, สารบัญในหน้า และการค้นหา

auth, backup, notify, demo

ฟังก์ชันหน้าที่
auth.Hash, auth.Verifyhash รหัสผ่านด้วย PBKDF2-SHA256 (600,000 รอบ, salt สุ่ม) และตรวจแบบเวลาคงที่
auth.Sign, auth.Parseสร้างและตรวจ cookie session ที่เซ็นด้วย HMAC (มีวันหมดอายุและ epoch ของบัญชี)
auth.Limiter.Fail, auth.Limiter.Blockedนับการใส่รหัสผิดตาม username + ที่อยู่, ที่อยู่ และ username แล้วบอกว่าต้องรอนานเท่าไร
backup.Manager.Run, backup.Manager.Create, backup.Manager.Pruneสำรองตามเวลา, สร้างไฟล์สำรอง .json.gz, ลบไฟล์ที่เก่ากว่าระยะเก็บ
backup.Decodeอ่านไฟล์ที่อัปโหลด (.json.gz หรือ .json) โดยจำกัดขนาดหลังคลายบีบอัด
notify.Daily, notify.NextRun, notify.Telegram.Sendตั้งเวลารายวันตาม timezone และส่งข้อความ Telegram
demo.Catalog, demo.NewSource, demo.SeedFindings, demo.SeedIncidentsข้อมูล demo: 21 site, ปฏิทินปลอมที่สร้างนัดรอบวันนี้, finding และ incident ตัวอย่าง
