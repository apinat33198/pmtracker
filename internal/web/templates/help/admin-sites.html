หน้านี้สำหรับ admin อธิบายการจัดการ site และ PM task ที่ Admin › Sites and tasks ถ้าจะตั้งหลาย site พร้อมกัน ใช้ Import จะเร็วกว่า

รายการ site

ตารางแสดงทุก site ที่ใช้งานอยู่: รหัส ชื่อ ภูมิภาค ชื่ออื่น จำนวน task และสถานะที่เร่งที่สุด กด Edit เพื่อแก้ site ที่ archive แล้วอยู่ในตารางแยกด้านล่าง

เพิ่ม site

ฟอร์ม Add a site ท้ายหน้ารายการ:

  1. Code: รหัสสั้นที่ vendor ใช้ในชื่อนัด เช่น BKK1 ต้องไม่ซ้ำกับ site อื่น
  2. Name และ Region: ภูมิภาคใช้จัดกลุ่มแถวในหน้า Overview และเป็นตัวกรอง
  3. Other names: ชื่ออื่นที่อาจอยู่ในชื่อนัด คั่นด้วยจุลภาค ใช้ภาษาไทยได้ เช่น บางนา, Bang Na DC
  4. PM tasks: ทุก system มีหนึ่งแถว เลือก vendor ของ system ที่ site นี้มี (เว้นว่าง = ไม่มี) และใส่วัน PM ล่าสุดถ้ารู้ เพื่อให้คำนวณวันครบกำหนดได้ทันที vendor ใหม่เลือก Add a new vendor… แล้วพิมพ์ชื่อ
  5. กด Add site

system เดียวกันที่มีสอง vendor (เช่น UPS สองห้อง) ให้เพิ่ม vendor ที่สองจากหน้า site หลังบันทึก ถ้าไม่มี system ที่ต้องการในรายการ เพิ่มที่ Systems ก่อน

แก้ site

  • Code: เปลี่ยนรหัสได้ รหัสเดิมจะถูกเก็บเป็นชื่ออื่นให้อัตโนมัติ นัดที่ใช้รหัสเก่าจึงยังจับคู่ได้
  • Other names: ระบบหาคำเหล่านี้ในชื่อนัดและสถานที่ (location) ของนัด ถ้านัดของ site นี้ไปค้างใน Review inbox บ่อย ให้เพิ่มคำที่ vendor ใช้ไว้ที่นี่
  • Notes: หมายเหตุของ site

เพิ่ม PM task

ในหน้าแก้ site ที่ Add a PM task:

ช่องความหมาย
System, Vendorอุปกรณ์และผู้ทำ PM
Every … monthsรอบ PM ค่าเริ่มต้น {{.Cfg.Defaults.IntervalMonths}} เดือน ใช้ 1, 6 หรือ 12 ได้
Last PM dateวัน PM ล่าสุด (ไม่บังคับ) ระบบบันทึกเป็น visit ที่ทำแล้วในวันนั้น
CycleFrom the last visit: นับรอบจาก PM ครั้งล่าสุด หรือ Fixed contract slots: ใช้วันตามสัญญาตายตัว (ต่างกันอย่างไร)
First slot dateสำหรับ Fixed contract slots คือวัน PM แรกตามสัญญา (จำเป็น) สำหรับ From the last visit คือวันครบกำหนดแรกเมื่อยังไม่มีประวัติ
Notesแสดงในหน้า task เช่น New UPS room, level 3

แก้ PM task

กด Edit ในตาราง task ของ site (หรือ Edit task ในหน้า task) นอกจากช่องข้างบน ยังตั้งค่าเฉพาะ task นี้ได้:

  • Booking window ± … days: นัดที่ห่างวันครบกำหนดไม่เกินนี้นับว่าตรงรอบ (ค่าเริ่มต้น {{.Cfg.Defaults.WindowDays}})
  • Remind … days before due: เริ่มเตือน Due soon ล่วงหน้ากี่วัน (ค่าเริ่มต้น {{.Cfg.Defaults.LeadDays}})
  • Overdue after … days: ช่วงผ่อนผันหลังวันครบกำหนดก่อนเป็น Overdue (ค่าเริ่มต้น {{.Cfg.Defaults.GraceDays}})
  • Paused: หยุดคำนวณและเตือน ใช้เมื่ออุปกรณ์เลิกใช้ชั่วคราวหรือสัญญาหมด ประวัติยังอยู่

เปลี่ยน system หรือ vendor ของ task ได้โดยประวัติ visit ยังอยู่ ถ้าทั้ง vendor เปลี่ยนสัญญา ใช้การย้าย task ที่ Vendors จะเร็วกว่า

Set the last PM date ในหน้าแก้ task บันทึก visit ที่ทำแล้วในวันที่เลือก ใช้เมื่อ visit นั้นไม่อยู่ในปฏิทิน

ข้อจำกัดไม่มีต้องพิมพ์รหัส site เพื่อยืนยัน และลบไม่ได้ถ้ามี incident เพราะเป็นหลักฐาน

ในเกือบทุกกรณีให้ใช้ archive ลบเฉพาะ site ที่สร้างผิด

ลบ task

Delete task ลบ visit ที่บันทึกเองของ task นั้นด้วย นัดในปฏิทินยังอยู่และเชื่อมใหม่ได้ finding และ incident ที่ผูกกับ task ยังอยู่ที่ site เดิม ถ้าต้องการเก็บประวัติไว้ ให้ pause แทนการลบ

ทุกการเปลี่ยนแปลงในหน้านี้ถูกบันทึกใน activity log ว่าใครเปลี่ยนอะไรเมื่อไร
