PM Tracker ใช้งานจริงใน Proxmox container (Debian LXC แบบ unprivileged) ผู้ใช้เข้าผ่าน Cloudflare Tunnel ที่ pm.apin.at ส่วนเครื่อง Mac ใช้พัฒนาเท่านั้น

Container

  • Debian 12 หรือ 13, 1 core, RAM 512 MB, ดิสก์ 4 GB
  • เปิด Options → Features → Nesting ไม่อย่างนั้น sandbox ของ systemd ทำงานไม่ได้และ service ล้มด้วย status=226/NAMESPACE
  • นาฬิกามาจาก Proxmox host จึงต้องเปิด NTP บน host (เวลาใน activity log ขึ้นกับมัน)
  • ให้ container มี IP คงที่ และตั้ง Proxmox firewall ให้เข้าพอร์ต 8080 ได้เฉพาะจากเครื่อง cloudflared

ติดตั้งและอัปเดต

ใน container (root):

apt install -y git
git clone https://github.com/apinat33198/pmtracker && cd pmtracker
deploy/install.sh pm.apin.at

install.sh ติดตั้ง Go รุ่นที่ยังได้รับ security fix ถ้ายังไม่มี (ตรวจ checksum), สร้าง config.json ครั้งแรก, build, ติดตั้ง systemd service, ตั้ง Cloudflare Tunnel ถ้าต้องการ (ตอบ n ถ้าใช้ cloudflared ที่มีอยู่แล้ว) และพิมพ์ลิงก์สร้าง admin คนแรก วาง service-account.json ไว้ในโฟลเดอร์ก่อนถ้ามี

อัปเดต:

cd ~/pmtracker && git pull && deploy/install.sh pm.apin.at

สคริปต์บันทึก data.json.before-update ก่อนรีสตาร์ต แก้ config ที่ ~/pmtracker/config.json เสมอ เพราะ install.sh เขียนทับ /etc/pmtracker/config.json

จาก Mac: deploy/install.sh root@<IP> pm.apin.at ทำแบบเดียวกันผ่าน SSH ส่วน deploy/push.sh root@<container> รันเทสต์ build บน Mac คัดลอก binary สำรองไฟล์ข้อมูล และรีสตาร์ต (ต้องใส่ SSH key ของ Mac ใน container ก่อน เพราะ Debian ไม่รับรหัสผ่าน root ผ่าน SSH)

ลอง branch ก่อน merge

cd ~/pmtracker && git fetch && git checkout help
deploy/install.sh pm.apin.at

branch ที่เพิ่มชนิดข้อมูลใหม่ (เช่น incidents) ใช้ไฟล์ข้อมูลเวอร์ชันใหม่ ถ้าถอยกลับไป main หลังบันทึกข้อมูลชนิดนั้นแล้ว ข้อมูลส่วนนั้นจะหายเมื่อ main บันทึกครั้งถัดไป และ main ไม่รับไฟล์สำรองจาก branch นั้น เก็บ data.json.before-update หรือกด Back up now ก่อนลอง

ลองบนเครื่องตัวเองก่อนได้เสมอโดยไม่แตะข้อมูลจริง: go run ./cmd/pmtracker -demo

Cloudflare Tunnel

  • cloudflared อยู่เครื่องอื่น (แบบที่ใช้อยู่): ตั้ง "listen": "0.0.0.0:8080", ใส่ IP ของเครื่อง cloudflared ใน trusted_proxies, ตั้ง route pm.apin.at → http://<IP ของ container>:8080 และ firewall ให้พอร์ต 8080 รับเฉพาะเครื่องนั้น
  • cloudflared อยู่ใน container เดียวกัน: "listen": "127.0.0.1:8080" และ route ไป http://127.0.0.1:8080 (ไม่ใช้ localhost ซึ่งอาจไปที่ IPv6 ก่อน) trusted_proxies ใช้ค่าเริ่มต้นได้
  • แนะนำให้ใส่ Cloudflare Access หน้า pm.apin.at (อีเมลบริษัท, one-time PIN หรือ Google) เป็นชั้นตรวจที่สองก่อนถึงการ sign in ของแอป ถ้าใช้ฟีด .ics ให้ทำ Access application แยกสำหรับ path forecast.ics แบบ Bypass

Log และสถานะ

systemctl status pmtracker
journalctl -u pmtracker -f                  # log สด
journalctl -u pmtracker | grep setup        # ลิงก์สร้าง admin คนแรก
journalctl -u pmtracker | grep activity:    # สำเนา activity log
curl -s http://127.0.0.1:8080/healthz       # ok

ไฟล์สำรองนอกเครื่อง

  1. เพิ่ม mount point ของ share บน NAS ให้ container ใน Proxmox เช่น /mnt/pm-backups
  2. ตั้ง "backup": {"dir": "/mnt/pm-backups"} ใน ~/pmtracker/config.json
  3. อนุญาตให้ service เขียนที่นั่น: systemctl edit pmtracker แล้วใส่ 
    [Service]
ReadWritePaths=/mnt/pm-backups
  4. รัน install.sh ใหม่ แล้วกด Back up now ที่ Admin › Backups เพื่อทดสอบ
  5. เพิ่ม backup job ของ container ใน Proxmox Backup Server ด้วย

Docker

docker build -t pmtracker .
docker run -v $PWD/config:/config -v pmdata:/data -p 8080:8080 pmtracker

mount config ที่ /config และ volume ข้อมูลที่ /data ถ้ามี proxy บน Docker network ให้ใส่ช่วง bridge เช่น 172.16.0.0/12 ใน trusted_proxies

ปัญหาที่พบบ่อย

อาการสาเหตุและวิธีแก้
service ล้ม 226/NAMESPACEcontainer ไม่ได้เปิด Nesting เปิดแล้วรีสตาร์ต container
ขึ้นว่า Google Calendar isn't connectedไม่มีไฟล์ key ที่ google.credentials_file วาง service-account.json ในโฟลเดอร์ repo แล้วรัน install.sh ใหม่
ปฏิทินขึ้น error 403 หรือ 404ยังไม่ได้แชร์ปฏิทินให้อีเมล service account หรือ Calendar ID ผิด รัน pmtracker -config /etc/pmtracker/config.json check
ไม่เริ่ม: config errorkey สะกดผิด, ค่าไม่ถูกรูปแบบ หรือ feed.token เป็นค่าตัวอย่างหรือสั้นกว่า 24 ตัวอักษร ข้อความ error บอกทุกข้อ
ใส่รหัสผ่านแล้วถูกพาไปหน้า HTTPSเปิดด้วย IP ในวง LAN ผ่าน HTTP ระบบไม่รับรหัสผ่านแบบนั้น ใช้ {{with .Cfg.PublicURL}}{{.}}{{else}}https://pm.apin.at{{end}}
ทุกคนถูกล็อกพร้อมกันtrusted_proxies ไม่มี IP ของ cloudflared ระบบเห็นทุกคนเป็นที่อยู่เดียวกัน ใส่ IP ตรงตัว (server เตือนใน log ถ้าใส่เป็นช่วง)
ลิงก์ setup ใช้ไม่ได้token เปลี่ยนทุกครั้งที่รีสตาร์ตจนกว่าจะมี admin คนแรก ดูลิงก์ล่าสุดใน journalctl
