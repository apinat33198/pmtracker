visit คือการมาทำ PM หนึ่งครั้ง ส่วนใหญ่มาจากนัดในปฏิทิน บางครั้งบันทึกเอง ตาราง visit อยู่ที่หน้า site (Recent visits) และหน้า task (Visits) ปุ่มในตารางนี้ใช้ได้เฉพาะ editor และ admin

อ่านตาราง visit

  • Date: วันนัด และเวลาถ้าไม่ใช่นัดทั้งวัน
  • Status: Scheduled, Done, unconfirmed, Done, Missed หรือ Cancelled (ความหมาย)
  • From: ชื่อนัดในปฏิทินและชื่อปฏิทิน หรือ Recorded by hand พร้อมหมายเหตุ ถ้าจับคู่ด้วยมือหรือด้วยกฎจะบอกไว้ (linked by hand, series rule, title rule)
  • Covers (หน้า site): task ที่ visit นี้ครอบคลุม

ยืนยันว่าทำแล้ว หรือ vendor ไม่มา

เมื่อวันนัดผ่านไป visit จะเป็น Done, unconfirmed และนับว่าทำแล้วไปก่อน หลังเช็กกับ vendor หรือรายงาน PM แล้ว:

  • กด Confirm done ถ้ามาทำจริง สถานะเป็น Done
  • กด Mark missed ถ้าไม่ได้มา visit จะไม่นับ วันครบกำหนดกลับไปคิดจาก PM ครั้งก่อน และ task อาจกลายเป็น Overdue ทันที ซึ่งถูกต้องแล้ว
  • กด Undo บน visit ที่ยืนยันหรือ mark ไปแล้ว เพื่อกลับเป็นสถานะเดิม

หน้า Overview แจ้งจำนวน visit ที่รอยืนยันไว้เสมอ ทุกการกดถูกบันทึกใน activity log ว่าใครทำเมื่อไร

บันทึก visit เอง

ใช้เมื่อ vendor มาโดยไม่มีนัดในปฏิทิน หรือเพื่อใส่ประวัติจากเอกสารกระดาษ:

  1. หน้า site: ที่ Record a PM visit ติ๊กทุก system ที่ทำในครั้งนั้น ใส่วันที่ (ห้ามเป็นวันในอนาคต) และหมายเหตุ เช่น เลขที่รายงานหรือชื่อช่าง แล้วกด Record visit
  2. หน้า task: ที่ Record a past visit ใส่วันที่และหมายเหตุ แล้วกด Record visit

visit ที่บันทึกเองเป็น Done ทันที ถ้าใส่ผิดให้กด Delete บนแถวนั้น (ลบได้เฉพาะ visit ที่บันทึกเอง)

การเลื่อนนัดและการยกเลิก

  • ถ้า vendor เลื่อนนัดในปฏิทิน ระบบใช้วันใหม่ และใต้ชื่อนัดแสดงว่า Moved from … to … พร้อมวันที่ระบบเห็นการเปลี่ยน
  • ถ้า vendor ยกเลิกนัด visit เป็น Cancelled และไม่นับ ถ้าไม่มีนัดใหม่ task จะไปตามสถานะปกติ เช่น Due soon หรือ Overdue

บันทึกสิ่งที่พบจาก visit

ปุ่ม Log finding บน visit ที่ทำแล้ว เปิดฟอร์ม finding ที่กรอกวันที่ site และ system ให้แล้ว ใช้บันทึกสิ่งที่ vendor หรือทีมเจอระหว่าง PM เช่น ค่าที่วัดได้เกินเกณฑ์ (Findings)
