PM Tracker อ่าน Google Calendar ด้วย service account (บัญชีสำหรับโปรแกรม) ซึ่งเห็นเฉพาะปฏิทินที่แชร์ให้ และอ่านได้อย่างเดียว ตั้งค่าครั้งเดียว แล้วเพิ่มหรือเอาปฏิทินออกจากหน้าเว็บได้

ต่อ Google Calendar (ครั้งแรก)

  1. ใน Google Cloud Console สร้าง project เปิดใช้ Google Calendar API สร้าง service account แล้วดาวน์โหลด key แบบ JSON
  2. วางไฟล์ key บนเซิร์ฟเวอร์ตามที่ google.credentials_file ใน config ชี้ไว้ (ปกติคือ /etc/pmtracker/service-account.json) ถ้าติดตั้งด้วย install.sh ให้วาง service-account.json ไว้ในโฟลเดอร์ repo แล้วรัน install.sh ใหม่
  3. รีสตาร์ต service ก่อนมี key ระบบยังทำงานได้แต่ขึ้นว่ายังไม่ได้ต่อ Google
  4. แชร์ปฏิทิน PM แต่ละอันให้อีเมลของ service account (…@….iam.gserviceaccount.com แสดงในหน้า Calendars and sync) ด้วยสิทธิ์ See all event details ถ้าเป็น Google Workspace admin อาจต้องอนุญาตการแชร์ออกนอกโดเมน
  5. รัน pmtracker -config /etc/pmtracker/config.json check เพื่อตรวจ key และทุกปฏิทิน คำสั่งนี้บอกว่าแต่ละปฏิทินมี event กี่รายการ และจับคู่ได้กี่รายการ

เพิ่มปฏิทิน

ที่ Add a calendar:

  • Calendar ID: หาใน Google Calendar → Settings and sharing → Integrate calendar
  • Label: ชื่อที่แสดงในแอป
  • Belongs to site: ใช้กับ site ที่มีปฏิทินของตัวเองและไม่ใส่รหัส site ในชื่อนัด
  • Every event is a PM visit: ติ๊กสำหรับปฏิทินที่มีแต่นัด PM ระบบจะไม่ต้องหาคำว่า PM ในชื่อนัด

แต่ละปฏิทินแสดงเวลาที่ sync ล่าสุด และข้อผิดพลาดถ้ามี กด Stop tracking เพื่อเลิกอ่าน event ที่อ่านมาจากปฏิทินนั้นจะถูกลบออกจากระบบ (ไม่กระทบ Google Calendar)

การ sync

  • อ่านทุก {{.Cfg.SyncIntervalMinutes}} นาที (sync_interval_minutes) และเมื่อมีคนกด Sync now
  • ครั้งแรกอ่านย้อนหลัง {{.Cfg.SyncLookbackMonths}} เดือน (sync_lookback_months) จากนั้นอ่านเฉพาะที่เปลี่ยน
  • ถ้า Google ให้อ่านใหม่ทั้งหมด (เกิดเป็นครั้งคราว) ระบบอ่านแค่ {{.Cfg.SyncLookbackMonths}} เดือนย้อนหลัง ประวัติ PM ที่เก่ากว่านั้นจะหายจากระบบ ถ้า audit ต้องย้อน 3 ปี ให้ตั้งเป็น 36
  • เมื่ออ่านไม่สำเร็จ จุดสถานะเป็นสีแดง และทุกหน้ามีแถบแจ้งสาเหตุ เช่น ยังไม่ได้แชร์ปฏิทินให้ service account

ระบบจับคู่ event อย่างไร

ลำดับที่ระบบใช้ ข้อแรกที่ตรงเป็นผล:

  1. การตัดสินใน Review inbox หรือ กฎที่จำไว้ (recurring series เดียวกัน หรือชื่อเดียวกัน)
  2. สัญญาณว่าเป็น PM: อยู่ในปฏิทินที่ติ๊ก Every event is a PM visit, ชื่อขึ้นต้นด้วย [PM], มีคำว่า PM เป็นคำเดี่ยว (ไม่ใช่ 3 PM), preventive maintenance, บำรุงรักษา, ซ่อมบำรุง หรือคำใน keywords ของ config{{with .Cfg.Keywords}} (เซิร์ฟเวอร์นี้: {{range $i, $k := .}}{{if $i}}, {{end}}{{$k}}{{end}}){{end}}
  3. site: จากปฏิทินที่ผูกกับ site, ไม่อย่างนั้นจากรหัสหรือชื่ออื่นของ site ในชื่อนัด, แล้วในสถานที่ (location), แล้วในรายละเอียด
  4. system จากชื่อ system หรือชื่ออื่นในชื่อนัด และ vendor จาก – ชื่อ vendor ท้ายชื่อแบบ [PM], โดเมนอีเมลของผู้จัดหรือผู้ร่วมนัด หรือชื่อ vendor ในข้อความ
  5. เลือก task ของ site ที่ตรงกับ vendor และ system ถ้า system นั้นที่ site นั้นมี vendor เดียว นัดไม่ต้องระบุ vendor ก็ได้ ถ้ามีสอง vendor และนัดไม่บอก นัดจะไปที่ Review inbox พร้อมสองตัวเลือก

นัดหนึ่งครอบคลุมได้หลาย system เช่น [PM] BKK1 DC, UPS – VoltEdge เมื่อ VoltEdge ทำทั้งสองระบบที่ BKK1 ผลและเหตุผลของทุกนัดดูได้ที่หน้า Events

Learned rules

กฎที่สร้างจาก Review inbox เมื่อเลือก Every event in this recurring series หรือ Every event titled … แต่ละกฎบอกว่าตรงกับอะไรและผูกกับ task ไหน กด Delete rule เพื่อลบ เช่น เมื่อเปลี่ยน vendor แล้ว series เดิมไม่ใช่ของ task เดิม

Forecast feed และ Daily digest

ส่วนท้ายของหน้าแสดงลิงก์ฟีดปฏิทินคาดการณ์ (ถ้าตั้ง feed.token) และตัวอย่าง digest ของวันนี้ ตั้งค่าทั้งสองใน config (config.json) ผู้ใช้อ่านรายละเอียดได้ที่ Digest, ปฏิทิน และ CSV
