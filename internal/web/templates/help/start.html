PM Tracker ติดตามงานบำรุงรักษาเชิงป้องกัน (preventive maintenance, PM) ของห้อง DC และ CSR ทุก site ระบบอ่านนัดหมายที่ vendor ส่งเข้า Google Calendar แล้วจับคู่กับงาน PM ของแต่ละ site บอกได้ว่าแต่ละระบบทำ PM ครั้งล่าสุดเมื่อไร ครั้งต่อไปควรเป็นเมื่อไร และอะไรที่เลยกำหนดหรือยังไม่ได้นัด

ระบบนี้อ่านปฏิทินอย่างเดียว ไม่สร้างหรือแก้นัดใน Google Calendar การนัด vendor ยังทำทางเดิม PM Tracker ช่วยให้เห็นภาพรวมและไม่มีงานไหนหลุด

คำที่ใช้ทั้งแอป

Site
ห้อง DC หรือ CSR หนึ่งแห่ง มีรหัสสั้น (เช่น BKK1) ชื่อ และภูมิภาค รหัสและชื่ออื่นของ site ใช้จับคู่กับชื่อนัดในปฏิทิน
System
ชนิดอุปกรณ์ที่ต้องทำ PM เช่น DC power, UPS, CRAC, Generator แต่ละ system เป็นหนึ่งคอลัมน์ในหน้า Overview
Vendor
บริษัทที่มาทำ PM มีผู้ติดต่อ เบอร์โทร อีเมล และ email domain ที่ใช้จับคู่นัดในปฏิทิน
PM task
หน่วยที่ระบบติดตาม คือ “system หนึ่งที่ site หนึ่ง ทำโดย vendor หนึ่ง” เช่น BKK1 UPS โดย ABC Power แต่ละ task มีรอบ PM ของตัวเอง (ค่าเริ่มต้นทุก {{.Cfg.Defaults.IntervalMonths}} เดือน) ถ้า system เดียวกันที่ site เดียวกันมีสอง vendor ก็เป็นสอง task
Visit
การมาทำ PM หนึ่งครั้ง มาจากนัดในปฏิทิน หรือคนบันทึกเองก็ได้ visit หนึ่งครั้งครอบคลุมได้หลาย task ถ้า vendor ทำหลายระบบในวันเดียว
Event
นัดหนึ่งรายการใน Google Calendar ที่ระบบอ่านมา event ที่จับคู่กับ task ได้จะกลายเป็น visit ส่วนที่ระบบไม่แน่ใจจะไปรออยู่ใน Review inbox
สถานะ (status)
ตำแหน่งของ task ในรอบ PM เช่น Overdue หรือ Booked ดูรายละเอียดที่ สถานะและการคำนวณรอบ PM

ข้อมูลไหลอย่างไร

  1. vendor ส่งนัดเข้าปฏิทิน PM ที่แชร์ให้ระบบ (หรือทีมลงนัดเอง)
  2. ทุก {{.Cfg.SyncIntervalMinutes}} นาที ระบบอ่านปฏิทินที่ติดตามอยู่ (กด Sync now เพื่ออ่านทันทีได้)
  3. ระบบดูชื่อนัด สถานที่ ผู้จัด และผู้ร่วมนัด เพื่อหาว่าเป็น PM หรือไม่ เป็นของ site ไหน ระบบไหน vendor ไหน ถ้ามั่นใจก็สร้าง visit ถ้าไม่แน่ใจก็ส่งไป Review inbox ให้คนตัดสิน
  4. จาก visit ที่ทำแล้วครั้งล่าสุด ระบบคำนวณวันครบกำหนดครั้งถัดไปและสถานะของทุก task
  5. หน้า Overview, digest รายวัน และฟีดปฏิทินแสดงผลลัพธ์ทั้งหมด

visit ที่ผ่านไปแล้วจะนับว่าทำแล้วทันที แม้ยังไม่มีใครยืนยัน (Done, unconfirmed) เพื่อไม่ให้งานขึ้นว่าเลยกำหนดเพียงเพราะยังไม่มีคนกด ถ้า vendor ไม่ได้มาจริง ให้กด Mark missed ดูที่ ยืนยันและบันทึก visit

บทบาทผู้ใช้

บทบาททำอะไรได้
viewerดูทุกหน้า และ export CSV
editorทุกอย่างที่ viewer ทำได้ และตัดสิน event ใน Review inbox, ยืนยันหรือ mark missed visit, บันทึก visit เอง, กด Sync now, เพิ่มและปิด ad-hoc job, บันทึกและปิด finding และ incident
adminทุกอย่างที่ editor ทำได้ และจัดการ site, task, vendor, system, ปฏิทิน, import, backup, ผู้ใช้, ดู activity log, ลบ finding และ incident, ปิด incident ที่ความเสี่ยงคงเหลือยังสูง

ผู้ใช้ทั่วไป

  1. เปิด Overview ดูช่องสีแดง (Overdue) และสีเหลือง (Due soon) ก่อน
  2. ถ้ามีแถบเหลืองว่า “past visits are waiting for someone to confirm” ให้เข้าไปยืนยันที่หน้า site
  3. ดู Review inbox ว่ามี event รอตัดสินไหม
