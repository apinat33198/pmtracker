จัดการว่าใคร sign in ได้และทำอะไรได้ที่ Admin › Users และดูว่าใครทำอะไรเมื่อไรที่ Admin › Activity

admin คนแรก

ตอนเริ่มระบบครั้งแรกที่ยังไม่มีบัญชี เซิร์ฟเวอร์พิมพ์ลิงก์ใช้ครั้งเดียวลง log:

No accounts yet. Create the first admin at https://pm.example.com/setup?token=…

ดูได้ด้วย journalctl -u pmtracker | grep setup เปิดลิงก์ ตั้ง username และรหัสผ่าน แล้วจะ sign in เป็น admin คนแรก ลิงก์ใช้ไม่ได้อีกเมื่อมีบัญชีแล้ว (รีสตาร์ตก่อนสร้างจะได้ลิงก์ใหม่)

เพิ่มและจัดการผู้ใช้

  • Add a user: username, บทบาท และรหัสผ่านเริ่มต้น (อย่างน้อย 10 ตัวอักษร) แจ้งรหัสให้เจ้าของบัญชี และให้เขาเปลี่ยนเองที่ Your account
  • Change: เปลี่ยนบทบาท (แต่ละบทบาททำอะไรได้)
  • Password or delete → Set password: ตั้งรหัสใหม่ให้คนที่ลืม เขาจะถูก sign out ทุกเครื่อง
  • Delete: ลบบัญชี session ของบัญชีนั้นหมดอายุทันที
  • admin คนสุดท้ายลดบทบาทหรือลบไม่ได้ และลบบัญชีตัวเองไม่ได้

หนึ่งคนหนึ่งบัญชีเสมอ บัญชีร่วมทำให้ activity log บอกไม่ได้ว่าใครทำอะไร ซึ่ง ISO 27001 ต้องการ

บัญชีสำรองใน config

admin กำหนดบัญชีใน auth.users ของไฟล์ config ได้ บัญชีนี้แก้จากเว็บไม่ได้ จึงยังใช้ได้แม้บัญชีในข้อมูลหาย (break-glass) ใส่รหัสผ่านเป็น hash จากคำสั่ง pmtracker hash-password ไม่ใส่รหัสตรง ๆ หน้า Users จะเตือนถ้ายังมีรหัสแบบข้อความธรรมดา

ล็อกตัวเองออก? เพิ่มบัญชีใน auth.users ด้วย hash แล้วรีสตาร์ต sign in ด้วยบัญชีนั้น แล้วตั้งรหัสใหม่ให้บัญชีของคุณที่ Admin › Users

Activity log

บันทึกว่าใครทำอะไรเมื่อไร และสำหรับการ sign in มาจาก IP ไหน:

  • sign in, sign out, ใส่รหัสผิด (ของบัญชีที่มีอยู่จริง) และการถูกล็อก
  • การเปลี่ยนบัญชีผู้ใช้
  • ทุกการเปลี่ยน site, task, vendor, system และปฏิทิน
  • การตัดสินใน Review inbox, การยืนยัน visit, job, finding และ incident
  • import, backup, restore และการดาวน์โหลด

การเก็บรักษา:

  • เก็บ {{with .Cfg.Activity.KeepDays}}{{.}}{{end}} วัน (activity.keep_days) แล้วลบ ISO 27001 ข้อ A.8.15 ให้กำหนดตามนโยบายของบริษัท
  • เก็บแยกจากข้อมูลหลัก ไฟล์ละหนึ่งวัน เขียนต่อท้ายอย่างเดียว ไม่มีอะไรในเว็บแก้หรือลบได้ และการ restore ไม่เปลี่ยนมัน (การ restore เองถูกบันทึก)
  • มีสำเนาใน log ของเซิร์ฟเวอร์: journalctl -u pmtracker | grep activity: ตั้ง journald ให้เก็บได้ 90 วัน หรือส่งต่อไปเซิร์ฟเวอร์ log กลาง
  • หน้า Activity แสดง 500 รายการล่าสุด Download all (CSV) ดาวน์โหลดทั้งหมดที่เก็บไว้สำหรับ audit (การดาวน์โหลดก็ถูกบันทึก)
  • root บนเซิร์ฟเวอร์ยังลบไฟล์ได้ ถ้าต้องการ log ที่คนบนเซิร์ฟเวอร์แก้ไม่ได้ ให้ส่ง log ออกไปที่อื่นและเก็บ backup ของ container
