ทุก PM task มีสถานะเดียว ณ วันนี้ สถานะบอกว่าต้องทำอะไรต่อ เรียงจากเร่งที่สุดไปน้อยที่สุดตามตารางด้านล่าง จุดสีหน้าชื่อ site ในหน้า Overview คือสถานะที่เร่งที่สุดของ site นั้น

สถานะของ PM task

สถานะหมายความว่าควรทำอะไร
Overdueเลยวันครบกำหนดมาเกิน {{.Cfg.Defaults.GraceDays}} วัน (ช่วงผ่อนผัน) และยังไม่มี visit ที่นัดไว้ตาม vendor ให้นัดทันที
Due soon, not bookedจะครบกำหนดภายใน {{.Cfg.Defaults.LeadDays}} วัน และยังไม่มีนัดขอให้ vendor ลงนัด
Off-cycleมีนัดแล้ว แต่ห่างจากวันครบกำหนดเกิน ±{{.Cfg.Defaults.WindowDays}} วันตรวจกับ vendor ว่าวันนัดถูกต้องไหม ถ้าเร็วไปหรือช้าไปมากรอบ PM จะเพี้ยน
No historyยังไม่มี PM ที่ทำแล้วในระบบ และยังไม่ได้ตั้งวันครบกำหนดแรก จึงคำนวณไม่ได้admin ตั้งวัน PM ล่าสุด หรือ editor บันทึก visit ย้อนหลัง หรือเชื่อม event เก่าใน Review inbox
Bookedมีนัดอยู่ในช่วง ±{{.Cfg.Defaults.WindowDays}} วันรอบวันครบกำหนดไม่ต้องทำอะไร รอวันนัด
On trackยังไม่ถึงช่วงที่ต้องนัดไม่ต้องทำอะไร

ตัวเลข {{.Cfg.Defaults.GraceDays}}, {{.Cfg.Defaults.LeadDays}} และ {{.Cfg.Defaults.WindowDays}} วันข้างบนคือค่าที่ตั้งไว้ในเซิร์ฟเวอร์นี้ แต่ละ task ตั้งค่าของตัวเองแทนได้ (admin ทำที่หน้าแก้ task: Booking window, Remind … days before due, Overdue after … days)

วันครบกำหนดคิดอย่างไร

ระบบดู visit ของ task นั้นทั้งหมด แล้วหา PM ครั้งล่าสุด คือ visit ที่ถึงวันแล้วและสถานะเป็น Done หรือ Done, unconfirmed จากนั้นคิดวันครบกำหนดตามรูปแบบรอบของ task:

From the last visit (ค่าเริ่มต้น)

วันครบกำหนด = วัน PM ครั้งล่าสุด + รอบ (เช่น 3 เดือน) ถ้า vendor มาช้าไปสองสัปดาห์ รอบถัดไปก็เลื่อนตามไปด้วย

Fixed contract slots

ใช้เมื่อสัญญากำหนดวัน PM ตายตัว เช่น ทุกไตรมาสนับจากวันเริ่มสัญญา วันครบกำหนดแต่ละรอบ = First slot date + n × รอบ คิดจากวันแรกทุกครั้ง ไม่ต่อจากรอบก่อน วันจึงไม่ค่อย ๆ เลื่อน ระบบเลือก slot แรกที่ช่วงจองเริ่มหลัง PM ครั้งล่าสุด ถ้า vendor มาช้า รอบถัดไปก็ยังเป็นวันเดิมตามสัญญา

กรณีอื่น

  • ยังไม่มีประวัติ แต่ตั้ง First slot date ไว้ในโหมด From the last visit: ใช้วันนั้นเป็นวันครบกำหนดแรก
  • ยังไม่มีประวัติและไม่มีวันแรก แต่มีนัดแล้ว: ใช้วันนัดเป็นวันครบกำหนด
  • ไม่มีอะไรเลย: สถานะเป็น No history

การบวกเดือน

การบวกเดือนจะไม่ล้นไปเดือนถัดไป: 30 พ.ย. + 3 เดือน = 28 ก.พ. (ไม่ใช่ 2 มี.ค.) และ 31 ส.ค. → 30 พ.ย. → 28 ก.พ. ในโหมด fixed slots

วันหยุด

ถ้าวันครบกำหนดตรงกับเสาร์ อาทิตย์ หรือวันหยุดที่ admin ใส่ไว้ใน config (holidays) หน้า task จะแนะนำวันทำงานที่ใกล้ที่สุดให้เสนอ vendor แทน

นัดและช่วงจอง

นัด (booked) คือ visit แรกที่สถานะ Scheduled และวันนัดยังไม่ผ่าน ช่วงจอง (booking window) คือวันครบกำหนด ± {{.Cfg.Defaults.WindowDays}} วัน นัดที่อยู่ในช่วงนี้นับว่าตรงรอบ (Booked) นัดที่อยู่นอกช่วงเป็น Off-cycle หน้า task แสดงช่วงจองเป็นแถบสีบน timeline และบอกว่านัดห่างจากวันครบกำหนดกี่วัน

สถานะของ visit

สถานะหมายความว่านับเป็น PM ที่ทำแล้วไหม
Scheduledนัดในอนาคตยัง
Done, unconfirmedวันนัดผ่านไปแล้ว ยังไม่มีใครยืนยันนับ
Doneมีคนกด Confirm done แล้ว หรือบันทึกเองนับ
Missedมีคนกด Mark missed: vendor ไม่ได้มาไม่นับ
Cancelledผู้จัดยกเลิกนัดในปฏิทินไม่นับ

ถ้าวันนัดผ่านไปแล้วแต่ vendor ไม่ได้มา ให้กด Mark missed ทันที มิฉะนั้นระบบจะนับว่าทำแล้วและเลื่อนรอบถัดไปให้ ทั้งที่จริงยังไม่ได้ทำ

ตัวอย่าง

UPS ที่ BKK1 รอบทุก 3 เดือน แบบ From the last visit, PM ครั้งล่าสุด 3 ก.ย. 2026:

  • วันครบกำหนด = 3 ธ.ค. 2026 ช่วงจอง = 12 พ.ย. ถึง 24 ธ.ค. (±21 วัน)
  • วันนี้ 17 พ.ย. ยังไม่มีนัด เหลือ 16 วัน (น้อยกว่า 30) → Due soon, not booked
  • vendor ลงนัด 13 ม.ค. 2027 ซึ่งห่างวันครบกำหนด 41 วัน เกิน 21 วัน → Off-cycle
  • vendor เลื่อนเป็น 1 ธ.ค. (อยู่ในช่วงจอง) → Booked
  • ถ้าไม่มีนัดเลยจนถึง 11 ธ.ค. (ครบกำหนด + 7 วัน) → Overdue
